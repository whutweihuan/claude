# Prism Farm（棱镜农场）设计文档

日期：2026-11-15

## 1. 意图与背景

做一款玩家自己长期挂着玩的农场放置游戏。核心体验是"安安静静、越来越大"：

- 从一小块地开始，亲手种、亲手收；
- 金币滚动，一格一格开垦，农场肉眼可见地变大；
- 中期买回自动化，农场开始自转，玩家退居"收钱和开新地"；
- 一张图经营成熟后进入全新地图（新作物、新风景），重走一遍"从小到大"；
- 离线时间也是游戏时间，回来只赚不亏。

**没有失败状态**：没有敌人、没有生命、没有任何会惩罚玩家离线的机制。放置游戏的底线是"不上线永远不会变差，上线永远有惊喜"。

预期节奏：每天上线 1~2 次、每次 2~5 分钟，**3~5 周**走完全部 5 张地图毕业。

## 2. 目标 / 非目标 / 反目标

**目标**

- 长线单线成长：地图 → 地块 → 作物 → 升级 → 自动化，只增不减。
- 离线收益完整结算 + 回来时的"离线收获报告"仪式感。
- 内容完全数据驱动，后期加地图/作物/升级**只写数据，不改系统**（玩家已明确要求保留后期开发能力）。
- 存档可导出/导入本地 JSON 文件；带版本号与迁移链。
- 深色玻璃拟态 + 有机生长感的现代 UI，柔和呼吸动效 + 明确收获反馈。

**非目标**

- 转生 / 重塑 / 赛季（玩家明确不要）。
- 成就系统、任务系统、每日签到（第一版不做；数据结构不阻碍日后加）。
- 移动端精细优化（能自适应不烂即可，主战场是 ≥1280px 桌面）。
- 多存档位（单存档 + 文件导出足够）。

**反目标**（技术上能做到但会让这东西算失败的东西）

- 任何形式的 FOMO 设计：限时活动、离线衰减、成熟作物枯萎、"再不回来就亏了"。
- 任何网络请求、外部 CDN、遥测。
- 弹窗打断式引导、强制教程。
- 用 `number` 参与金额运算（CLAUDE.md 红线）。

## 3. 核心循环

```
选作物种下(花 seedCost) → 等待生长 → 收获(得 yieldCoins) → 
金币 → 买地块/解锁作物/买升级/买自动化 → 单位时间收益上升 →
整图开垦完 + 付迁徙费 → 新地图（新作物组，循环重启，老图保留产出）
```

玩家动作只有三类：点地块（种/收/换种）、点商店（买）、切地图。其余交给时间与自动化。

## 4. 内容结构

### 4.1 五张地图

| # | 地图 | 气质 | 作物示例 | 地块数 | 起始解锁 |
|---|------|------|----------|--------|----------|
| 1 | 晨光菜园 | 新手村，节奏快 | 萝卜、白菜、向日葵、番茄… | 12 | 2 块 |
| 2 | 暖光花房 | 温室，第一波自动化 | 兰花、多肉、郁金香… | 14 | 2 块 |
| 3 | 半山果园 | 果树慢轮次、高单价 | 草莓、蓝莓、蜜桃… | 16 | 3 块 |
| 4 | 镜湖田埂 | 水作、风物 | 芦苇、莲藕、菱角… | 18 | 3 块 |
| 5 | 极光学园 | 终章，幻想作物 | 星霜花、月见藤… | 20 | 4 块 |

（作物名与数值表是实现期的内容数据文件，允许建造者在保持"每图 6~8 种"前提下微调命名；表结构见 §9。）

### 4.2 解锁规则

- **地块**：每张图的地块按从左到右、从上到下顺序开垦，第 n 块价格 = `该图基准价 × 1.9^(n-1)`（基准价与该图作物经济挂钩，保证买下一块的等待时间在分钟~小时级，不出现卡死几天）。
- **作物**：每张图内作物分两档 —— 前 3~4 种随进度自动可用，其余花一次性 `unlockCost` 解锁。解锁后永久可种。
- **换图**：当前图 **全部地块已开垦** 且支付"迁徙费"（≈ 该图满地块全自动状态下 6~10 小时产出），即解锁下一张图。老地图保留全部地块与产出，自动化继续工作。
- 游戏"毕业"状态 = 第 5 张图全开垦且主要升级买齐，进入无尽观赏模式（数值上仍微有增长空间，见 4.4 无限档）。

### 4.3 升级与自动化（每图商店）

每条升级线在**每张图内独立购买**（跨图不共享，给每张新图重新铺垫成长感）：

| 线 | 类型 | 效果 | 备注 |
|----|------|------|------|
| 沃土 | 可重复购买 ×N | 该图收获价值 +25%/级 | 价格几何增长 |
| 光合 Prism | 可重复购买 ×N | 该图生长速度 +10%/级，上限 +100% | 到顶后关闭 |
| 自动收获 | 一次性 | 到熟自动收，收完停在那块地等手动种 | |
| 自动补种 | 一次性 | 需先买自动收获；自动收后按**该地块预设作物**立即补种（补种同样扣 seedCost，见 §4.5），实现全自转。预设作物默认为玩家最近一次手种的作物，可随时在地块详情里更换（见 §7.1）—— 这是全自转后解锁新作物仍能铺进老地块的通道 | |
| 离线 lamp | 全局一次性 ×2 | 离线结算上限 8h → 24h → 72h | 全游戏共享，只此一条跨图 |

自动化阶梯由此形成：**前期全手动 → 该图买了自动收获，半手动 → 再买自动补种，该图完全自转**。终局状态：五图全自转，玩家上线只看报告、开新内容。

### 4.4 数值骨架

- 每张图 6~8 种作物，按顺序：`growTime` 约 ×4 递增，单次收获 `yieldCoins` 约 ×5 递增（后一种单位时间收益约为前一种 ×1.25~1.4，"多种一棵更赚"要始终成立）；`seedCost` ≈ 前一种 `yieldCoins` 的 40~60%（回本周期 ≈ 1.5~2.5 个生长周期）。
- **硬约束：每种作物 `yieldCoins > seedCost`**（单轮净利恒正），这是 §4.5 记账模型与"离线只赚不亏"的前提，进 §9 内容断言。
- 跨图基准收益约为上一图的 ×500~×1000，保证进新图有"暴发感"，同时新图基准价也水涨船高。
- 第 5 图终局：沃土继续可买但价格 ×2.4/级，作为无尽软上限。
- 所有金币运算用 `break_infinity.js` 的 `Decimal`。`number` 只允许出现在：生长时间（ms）、百分比系数、UI 动画参数。

具体数值表是 `src/game/content/` 下的数据文件，实现时生成后必须过 §10 的节奏断言测试。

### 4.5 离线结算规则

设 `elapsed = min(now - lastSeenAt, offlineCap)`，对每个地块按 wall-clock 差值推导：

| 自动化状态 | 结算结果 |
|------------|----------|
| 全手动 | 生长进度推进；到熟停在地里等收（不枯萎、不补轮） |
| 自动收获 | 到熟收 1 次，随后停（没种子补种就是没种） |
| 自动收获+补种 | 逐轮结算"收(+yieldCoins) + 种(−seedCost)"，直至 `elapsed` 耗尽，余数作为当前生长进度；**某轮种不下（金币 < seedCost）则停在"已收未种"状态**，绝不透支为负 |

**记账统一原则**（在线/离线同一函数的成立前提）：任何一次"种下"动作都扣 `seedCost` —— 手动种、在线自动补种、离线模拟补种，一视同仁；任何一次收获都加 `yieldCoins`。数值表保证每种作物 `yieldCoins > seedCost`（周期净利恒正，见 §4.4），所以"回来只赚不亏"依然成立，且同一段时长在线逐步结算与离线一次结算必然相等。

回来后弹"离线收获报告"：离开时长、每张图收获轮数、总金币（数字滚动动画）。**收益在加载结算时即已入账，报告纯仪式展示**，不做 pending 领取状态（避免"看了报告才能花钱"的多余门槛；关页幂等重算也因此天然成立）。**任何情况下离线不会比在线等同样时长拿得少**（同一套结算函数服务在线/离线，见 §9）。

## 5. 存档

- Zustand `persist` 中间件写 `localStorage`（key: `prism-farm-save`）。
- **所有金额字段序列化时是 string**（`Decimal.toString()`），反序列化 `new Decimal(str)`。禁止 JSON 里出现金额 number。
- 顶层 `schemaVersion: number` + 迁移注册表（`v1→v2→…` 纯函数链）。加载时从存档版本逐级迁移到当前版本。
- **导入/导出**：设置面板内导出为 `prism-farm-save-<日期>.json` 下载文件；导入走 `<input type="file">` 本地解析。导入前跑同一套校验 + 迁移。
- **读取安全**（沿用本仓库沉淀的存档安全经验）：解析失败 ≠ 损坏 —— 读 localStorage 抛异常/JSON 解析失败时，**不得**自动开新局覆盖：进入"本次不写盘"模式，界面提示并允许导出原始文本自救；只有校验（非读取失败）不过才提示用户手动重置。
- 校验：数值字段全为合法十进制字符串、schemaVersion 存在、未知 mapId/cropId 采取"忽略但保留原始数据"策略（前向兼容：旧版本能读未来存档不炸内容）。
- 提供"重置存档"入口（二次确认 + 长按）。

## 6. 游戏循环与时间模型

- **真值源是 wall-clock**：每块地记录 `plantedAt`、作物 id、有效 `growTime`（含当时生效的光合倍率快照）。渲染时 `progress = clamp((now - plantedAt) / growTime)`。
- UI 心跳：`setInterval` ~10Hz 触发 React 重渲染；**不**用累加 tick 的方式推进逻辑（后台标签页节流也不出错）。
- 收获结算（在线）：自动收获线在每个心跳检查 `progress >= 1` 的地块，按 §4.5 规则结算；`lastSeenAt` 在每次心跳更新，页面被杀后重开即走离线结算路径 —— **在线/离线同一套纯函数**。
- 时间来源 = `Date.now()`。不做反作弊（单机自娱，改时间属于"玩家自己的体验"）。

- 移动端（≥375px）：地图侧栏收成顶部横向标签，右面板折叠为底部抽屉。只求可玩不烂。
- 未解锁地图标签灰显 + tooltip 显示解锁条件（"开垦全部 12 块地并支付 X 币迁徙"）。
- **地块点击语义**：空地 → 弹作物选择（即时种植，扣 seedCost）；成熟 → 收获；生长中 → 打开地块详情面板，提供两个动作：**"更换预设作物"**（只改下一次补种的作物，当前轮不打断，全自动地块换新作物的正路）与 **"清茬改种"**（立即铲掉当前作物，进度作废不折价，重新选种扣新 seedCost —— 给玩家止损/试验的自由，成本自己负责）。

### 7.2 视觉语言

- 深色玻璃拟态：半透明面板 + `backdrop-blur` + 细边框高光；每张图有自己的主题色相（菜园暖绿、花房粉光、果园橙金、镜湖青蓝、极光紫青），影响粒子、面板描边、作物描光。
- 动效规范：收获反馈 = 缩放弹跳 + 金币飘字（Framer Motion，`layoutId` 共享元素从地块飞向左上角金币 HUD）；购买 = 面板微沉 + 勾选描边动画；数字 = 缓动滚动。环境 = CSS `@keyframes` 呼吸（作物 SVG `transform: scaleY(1±0.02)`），粒画布只跑装饰层，绝不含游戏逻辑。
- 作物美术：**不做 35 张手绘图**。做一个参数化 SVG 组件 `<PlantSprite>`：由"茎/叶/花/果/藤/穗"图元 + 每种作物的配色与形态参数（数据文件里的字段）组合生成，保证 35 种作物外观可辨且风格统一，新作物零美术成本。
- 成熟地块呼吸高亮 + 轻微辉光，"该收了"的暗示不打扰但一定被注意到。

### 7.3 字体与音效

- 字体：`@fontsource/inter`（npm 安装，woff2 打进产物，运行时零外链）；中文回退系统字体栈；金额数字 `font-variant-numeric: tabular-nums`。
- 音效：Howler.js，默认静音（CLAUDE.md 红线），设置面板开关 + 音量。音效文件用 `tools/gen-sounds.mjs` 以 Node 脚本合成 4 个短 wav（收获、购买、解锁、迁徙），提交进 `public/sounds/` —— 不下载任何第三方素材，保持全离线与可复现。

## 8. 状态与架构

```
src/
  game/
    content/        # 纯数据: maps.ts crops.ts upgrades.ts 表结构+数值(扩展点①)
    types.ts        # CropDef/MapDef/UpgradeDef/GameState 等
    systems/        # 纯函数无 React 依赖: growth.ts purchases.ts offline.ts
                    # validator.ts migrate.ts format.ts(数字格式化)
  store/            # zustand + immer + persist; action 只做调用 systems 后写 state
  ui/               # React 组件; HUD/MapGrid/Plot/Shop/panels/OfflineReport/
                    # Settings/PlantSprite/BackgroundCanvas
  tools/gen-sounds.mjs
```

架构原则：

1. **系统层是纯函数**：输入 `GameState + GameEvent + nowMs`，输出新的 state 切片。React 只是渲染器。Vitest 直接测 systems，不需要 DOM。
2. **内容即数据**：系统与组件不出现 `if (cropId === 'radish')`。新加一张地图 = 新增 MapDef + CropDef[] + 主题色参数，系统零改动（扩展点②）。
3. **数字格式化**统一走 `format.ts`：1234 → `1.23K`，阈值 K/M/B/T/Qa…，与 break_infinity 量级对齐；所有 UI 金额经此显示。
4. 事件流单向：UI dispatch → store action → systems 纯计算 → immer 写入 → 渲染。无组件内金额运算。

## 9. 测试（Vitest）

必须覆盖：

- `growth`：任意 `plantedAt/growTime/now` 组合下进度正确；成熟判定边界。
- `purchases`：钱不够/已拥有/前置未满足（自动补种需先有自动收获）拒绝且状态不变；扣款与效果正确。
- `offline`：§4.5 三档自动化 × 时长边界（0、刚好 N 轮、N 轮+余数、超过 cap）；同一段时长"在线逐步结算"与"离线一次结算"结果一致（一致性是核心保障）；**中途金币买不起补种种子 → 停在"已收未种"、余额恒 ≥ 0** 的用例；地块更换预设作物后离线按新作物轮转。
- `migrate`：v1 存档逐级迁移；未知 id 保留并忽略；损坏 JSON 走"不写盘"分支。
- `format`：阈值进位、大数量级（1e33+）、精度显示。
- `content 节奏断言`：遍历数据表 —— 每图回本周期单调、下一作物单位时间收益 > 上一作物、**每种作物 yieldCoins > seedCost**、地块价格曲线不出现超过 X 小时空窗（防止内容表改坏）。

## 10. 约束回顾（来自 CLAUDE.md，视为公理）

Vite `base: './'` 产物可 `file://` 双击运行；TS strict 禁 `any`；金额一律 Decimal；无网络请求/外部 CDN；Howler 默认静音；测试覆盖 systems/Formatter/OfflineCalc/存档迁移；不引 Redux/Pixi/Three 等。

## 11. 决策归属

**玩家已定**：长线放置、无转生、安安静静扩农场；"图内逐渐开垦 → 完成换全新地图全新作物"；前期手动→买自动化→终局自转；4~5 张图规模 + 保留后期开发能力。

**本文档（建造者侧）拍板**：地图数定为 5 及各自主题/规模；升级线四条（沃土/光合/自动化两件/全局离线 lamp）；离线三档结算规则与"离线不重扣种价"简化；数据驱动架构与参数化 SVG 美术方案；音效文件自合成、字体走 @fontsource；数值骨架公式（×1.9 地价、跨图 ×500~1000 等）；单存档 + 文件导入导出；"毕业"后无尽软上限。

**留给实现期**：具体作物命名与完整数值表（须过 §9 节奏断言）；SVG 图元造型；粒子视觉细节；文案措辞。

### 建造者检查轮裁定（2026-11-15，全部为建造者侧决定，玩家无需参与）

一位未参与对话的建造者代理按本文档试做计划，回报三个会返工级别的空白，已裁定并回写正文：

1. **补种记账统一**：每次种植（手动/在线自动/离线模拟）一律扣 seedCost、收获一律加 yieldCoins，配合"单轮净利恒正"硬约束，同时保住在线离线同一函数的一致性与"回来只赚不亏"（§4.5）。
2. **全自转后的换种通道**：地块增加"预设作物"概念 + 详情面板"更换预设作物 / 清茬改种"两动作（§4.3、§7.1），否则自动化地块永远复种旧作物，新作物铺不进去。
3. **离线报告不做领取态**：加载即入账，报告纯仪式（§4.5），省掉 pending 状态机与幂等领取分支。
