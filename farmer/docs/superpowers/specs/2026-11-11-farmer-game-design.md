# 小菜园（桌面种田挂机游戏）设计

日期：2026-11-11  
目标平台：Windows 10/11  
形态：本地桌面程序（Python 3.8 + Tkinter），双击即玩  
项目目录：`farmer/`

## 1. 意图

用户想要一个类似 QQ 农场简化版的桌面种田小游戏，在上班时偶尔瞄一眼：

- 打开窗口能看到一块菜地，作物按真实时间生长，状态随时间变化。
- 种下去之后可以去忙别的；关掉程序，菜仍然按真实时间继续长。
- 回来时收菜、卖钱，再买种子、开垦新地，有一点缓慢的养成感。
- 整体是休闲挂机，不需要盯着，也不惩罚遗漏。

这个游戏的价值在于“过一会儿回来有东西可收”的轻松感，而不是策略深度。

## 2. 目标

- 一块可视化的菜地，初始 4 块地，最多 8 块。
- 五种作物，成熟时间从 30 分钟到 8 小时，覆盖“上班收几轮”和“第二天早上收”两种节奏。
- 作物有可见的生长阶段（幼苗 → 生长 → 结果 → 成熟），进度条和倒计时实时刷新。
- 种植消耗金币买种子；收获后作物进入仓库，玩家从仓库卖出换金币。
- 浇水可以缩短生长时间，属于可选的小操作，不浇水只是慢，不会枯死。
- 金币足够时可以开垦新地。
- 进度按真实时间计算：窗口关着、电脑重启都不影响。
- 存档自动保存，下次打开接着玩；存档损坏时不崩溃。
- 提供“一键收获”，适合隔一段时间回来一次收完。
- 用自动化测试覆盖核心规则和存档，且做一次 GUI 冒烟测试。

## 3. 非目标

- 不做偷菜、好友、排行榜、联网、账号、云同步。
- 不做动物、加工坊、任务、成就、天气、季节、装饰、音效。
- 不做多存档、多角色。
- 不做仓库容量上限或仓库扩容，仓库无限存放。
- 不做手机端或网页版。
- 不做需要精确操作或计算的经营策略。
- 不使用外部图片素材或第三方依赖。

## 4. 反目标

以下情况即使技术上可行，也算设计失败：

- 出现惩罚性机制：作物枯死、虫害、偷菜导致损失。
- 需要用户持续盯着，或错过时间就会有损失。
- 用弹窗、系统通知、声音打扰正在工作的用户。
- 数值复杂到需要做攻略才能玩。
- 关掉程序后进度丢失或停止增长。

## 5. 用户已经定下的部分

- 平台：Windows 桌面程序，沿用用户已有小工具的风格（Python + Tkinter、`run_*.bat` 启动）。
- 使用场景：上班时偶尔瞄一眼；第二天也会打开。
- 可以关掉程序，关掉期间作物继续按真实时间生长。
- 有经济循环：收菜卖钱、买种子、买地，有养成感。
- 要有一个仓库：收菜先进仓库，再由玩家卖出。
- 有一点小事可做：浇水能加速，忘了浇不会死。
- 节奏：大部分作物 30 分钟到 2 小时，另有一两种 6～8 小时的过夜作物。

## 6. 留给建造者决定的部分（本设计的默认决定）

以下为本设计已经替建造者定下的默认值；实现时可以微调数值，但不要改变机制：

- 技术栈：Python 3.8.3、Tkinter 8.6、标准库；不引入 Pillow 或其他依赖。
- 独立目录 `farmer/`，不改动现有项目。
- 美术：用 Tkinter Canvas 绘制土壤、茎叶和果实，不使用 emoji 或图片素材。
  原因：Python 3.8 自带的 Tk 8.6 对 emoji 等非 BMP 字符支持不稳定，容易出现方块或空白。
- 文字：微软雅黑 UI（Microsoft YaHei UI），中文界面。
- 仓库：收获的作物先进入仓库，不自动卖钱；仓库按作物累计数量，支持“卖出某种作物的全部库存”和“全部卖出”。卖出是游戏内获得金币的唯一途径（初始金币除外）。
- 收获与卖出分离：一键收获只负责把成熟作物收进仓库；仓库面板固定在主窗口右侧，不需要弹窗切换。
- 存档：JSON 文件 `farmer/save.json`，与程序同目录；单人本地使用，不做用户目录迁移。
- 时间：使用 Unix 时间戳（`time.time()`），生长进度只依赖时间戳，不依赖窗口是否打开。
- 刷新：GUI 每 1 秒刷新一次进度和倒计时；不做后台线程。
- 窗口标题显示当前可收获数量，例如“小菜园（2 可收）”，方便瞄一眼就知道有没有东西收。
- 一键收获：一个按钮收掉所有成熟作物，金币合计到账。
- 不实现关闭到系统托盘；关闭窗口即退出并保存。

## 7. 数值设计

### 7.1 作物

| 作物 | 成熟时间 | 种子价 | 收获卖价 | 单块净赚 | 每小时单块利润 |
| --- | --- | --- | --- | --- | --- |
| 小白菜 | 30 分钟 | 10 | 25 | +15 | 30 |
| 胡萝卜 | 1 小时 | 25 | 65 | +40 | 40 |
| 番茄 | 2 小时 | 45 | 135 | +90 | 45 |
| 玉米 | 4 小时 | 80 | 260 | +180 | 45 |
| 南瓜 | 8 小时 | 140 | 480 | +340 | 42.5 |

设计意图：

- 短周期作物单位时间收益略低，但需要更频繁回来；长周期作物适合挂机过夜。
- 各作物每小时收益大致持平，玩家按自己的作息选择，不存在必须选某个作物的最优解。
- 所有作物单块收获 1 份，不引入随机产量。

### 7.2 土地与初始状态

- 初始金币：60。
- 初始已开垦土地：4 块（2×2 排列）。
- 第 5～8 块地的开垦价格依次为：200、500、1000、1800。
- 开垦后立即生效，不需要等待。

### 7.3 浇水

- 生长中的地块可以浇水，每次把剩余生长时间缩短“总生长时间的 10%”。
- 每次种植最多浇水 3 次（最多省 30% 时间）。
- 同一块地两次浇水之间至少间隔 10 分钟真实时间。
- 浇水不受“是否有人看着”影响，随时可用；不浇水不会产生任何负面状态。
- 成熟后不能再浇水。

### 7.4 生长阶段

按进度 p（0～1）划分：

| 进度 | 阶段 | 画面 |
| --- | --- | --- |
| 无作物 | 空地 | 棕色土壤，写“空地” |
| 0 ≤ p < 0.2 | 幼苗 | 小土堆 + 两片小叶子 |
| 0.2 ≤ p < 0.5 | 生长 | 茎 + 四片叶子，植株变高 |
| 0.5 ≤ p < 0.85 | 结果 | 植株 + 未成熟的小果实 |
| 0.85 ≤ p < 1 | 将熟 | 果实变大、接近作物颜色 |
| p ≥ 1 | 成熟 | 果实饱满、地块高亮、显示“收获” |

不同作物使用不同的果实颜色和形状参数，但共用同一套绘制流程。

## 8. 游戏规则

### 8.1 种植

- 玩家在底部种子栏选择一种作物，再点击一块空地种下。
- 种子栏显示作物名、成熟时间和种子价格；金币不足的种子置灰。
- 种植时立即扣除种子价格，记录种植时间戳。
- 金币不足时点击空地，状态栏提示“金币不够”。
- 已选中的种子在种植后保持选中，方便连续种多块地。

### 8.2 生长

- 剩余时间 = 成熟时间 −（当前时间 − 种植时间）− 浇水节省的时间。
- 剩余时间为 0 或负数即成熟。
- 允许系统时间向后调整：计算出的已生长时长小于 0 时按 0 处理。
- 关掉程序期间照常生长；重新打开时立即按当前时间结算。

### 8.3 收获

- 点击成熟地块或“一键收获”按钮完成收获。
- 收获后该作物数量 +1 进入仓库，地块变回空地，可以立刻再种。
- 累计收获次数 +1；收获本身不加金币。
- 收获时在对应地块上方短暂显示“+1 小白菜”之类的飘字（约 1 秒）。

### 8.4 开垦

- 顶部显示下一块地的价格和“开垦”按钮。
- 金币足够时按钮可用；点击后扣除金币并解锁一块新地。
- 8 块地全部开垦后，开垦按钮隐藏，显示“已全部开垦”。

### 8.5 统计

顶部显示：

- 当前金币。
- 累计收获次数。
- 累计收入（卖出所得，不含初始金币）。
- 下一块地价格 / 开垦按钮。

### 8.6 仓库与卖出

- 仓库按作物记录数量，初始为空；仓库容量无限。
- 仓库面板每行显示：作物名称、库存数量、单价、小计和“卖出”按钮。
- 点击某种作物的“卖出”：卖出该作物的全部库存，金币增加“数量 × 卖价”，该行数量清零。
- 点击“全部卖出”：把所有库存一次性卖出，金币合计到账，仓库清空。
- 某作物库存为 0 时，该行“卖出”按钮置灰；仓库全空时，“全部卖出”置灰并显示“仓库是空的”。
- 卖出是获得金币的唯一途径（初始金币除外）。

## 9. 界面

主窗口标题“小菜园”，初始尺寸约 1180×680，可调整大小但内容不随窗口缩放。

### 9.1 布局

```
+--------------------------------------------------------------------------------+
| 金币 120   累计收获 8 次   累计收入 200              [开垦 200]                 |  顶栏
+----------------------------------------------------------+---------------------+
|  +----------+ +----------+ +----------+ +----------+     | 仓库                |
|  |          | |          | |          | |          |     | 小白菜 ×3   25/个   |
|  |  菜地 1  | |  菜地 2  | |  菜地 3  | |  菜地 4  |     |        [卖出]       |
|  |          | |          | |          | |          |     | 胡萝卜 ×1   65/个   |
|  +----------+ +----------+ +----------+ +----------+     |        [卖出]       |
|  +----------+ +----------+ +----------+ +----------+     | 番茄 ×0     135/个  |
|  |  未开垦  | |  未开垦  | |  未开垦  | |  未开垦  |     |        [卖出]       |
|  +----------+ +----------+ +----------+ +----------+     | ...                 |
|                                                          | [全部卖出（190）]   |
+----------------------------------------------------------+---------------------+
| 种子： [小白菜 30分/10] [胡萝卜 1时/25] [番茄 2时/45] ...       [一键收获]       |  种子栏
+--------------------------------------------------------------------------------+
| 状态：点击空地种下小白菜                                                         |  状态栏
+--------------------------------------------------------------------------------+
```

图中文字仅用于说明布局，实际界面使用 Canvas 图形和微软雅黑 UI 字体。

### 9.2 地块卡片

每块地是一个固定尺寸的 Canvas（约 200×150），包含：

- 土壤背景和作物图形。
- 生长中：作物名、进度条、剩余时间（`还需 12:34`）、`浇水` 按钮。
- 成熟：高亮边框、`可收获` 字样和整块地可点击。
- 空地：`空地` 字样，点击即种植当前选中的种子。
- 未开垦：灰色土块和锁形图案（用线条绘制），不可点击；在顶栏开垦后变为空地。
- 浇水按钮在冷却中或已浇满 3 次时置灰，鼠标悬停不显示额外弹窗。

### 9.3 仓库面板

- 固定在主窗口右侧，宽约 280 像素，背景比菜地略浅，标题“仓库”。
- 五种作物各占一行：名称、`×数量`、单价、小计和`卖出`按钮。
- 数量为 0 时整行变淡，`卖出`按钮置灰。
- 面板底部是`全部卖出`按钮，按钮上显示当前库存总价值，例如“全部卖出（190 金币）”；仓库为空时按钮置灰。
- 卖出后对应行数量归零，状态栏提示“卖出小白菜 ×3，+75 金币”。

### 9.4 种子栏

- 五个作物按钮，显示名称、成熟时间和价格。
- 当前选中的按钮有明显高亮。
- 金币不足的按钮置灰但仍可点击并给出提示。
- 右侧有“一键收获”按钮；没有可收作物时置灰。

### 9.5 状态栏

显示最近一次操作的反馈，例如“种下了小白菜”“收获番茄 +135”“金币不够”“已开垦第 5 块地”。反馈文字保持 3 秒后恢复默认提示“选一种种子，点空地种下”。

### 9.6 窗口标题

格式为“小菜园”或“小菜园（2 可收）”，每秒随成熟状态更新。

## 10. 存档与时间

### 10.1 存档内容

`farmer/save.json`：

```json
{
  "version": 1,
  "coins": 120,
  "unlocked_plots": 4,
  "selected_crop": "xiaobaicai",
  "total_harvests": 8,
  "total_income": 200,
  "warehouse": {"xiaobaicai": 3, "fanqie": 1},
  "plots": [
    {
      "crop": "fanqie",
      "planted_at": 1762750000.0,
      "water_count": 1,
      "last_water_at": 1762750600.0
    },
    null,
    null,
    null
  ],
  "saved_at": 1762751200.0
}
```

- `plots` 长度始终为 8；`null` 表示空地。
- 未开垦的地块也在 `plots` 中，统一为 `null`，用 `unlocked_plots` 判断是否可用。
- `warehouse` 以作物 id 为键、非负整数为值；缺失时按空仓库处理，未知作物 id 忽略。
- 作物 id 使用拼音：`xiaobaicai`、`huluobo`、`fanqie`、`yumi`、`nangua`。

### 10.2 保存时机

- 每次种植、浇水、收获、卖出、开垦后保存。
- 每 10 秒自动保存一次。
- 关闭窗口时保存。

### 10.3 读取与容错

- 文件不存在：按初始状态新开一局。
- JSON 解析失败、字段缺失或类型不对：把原文件重命名为 `save.corrupt-<时间戳>.json`，按初始状态新开一局，并在状态栏提示“存档损坏，已开始新的一局”。
- 作物 id 无法识别：该地块按空地处理。
- 未知多余字段忽略，保证向前兼容。
- 关闭程序不会暂停生长；重新打开时按当前真实时间结算。

## 11. 结构与实现

```
farmer/
  farm_core.py        纯逻辑：作物表、地块状态、规则、存档读写
  farm_gui.py         Tkinter 界面与每秒刷新
  test_farm.py        核心逻辑测试
  test_gui_smoke.py   GUI 冒烟测试
  run_farmer.bat      Windows 双击启动
  README.md           玩法与运行说明
  save.json           运行时生成，不提交到 git
  docs/superpowers/specs/2026-11-11-farmer-game-design.md
```

### 11.1 核心接口

`farm_core.py` 不依赖 Tkinter，时间通过参数或可注入的时钟传入，便于测试。

- `CROPS`：作物定义表，包含 id、名称、成熟秒数、种子价、卖价、颜色参数。
- `LAND_PRICES`：第 5～8 块地的价格。
- `Plot`：作物 id、种植时间、浇水次数、上次浇水时间。
- `FarmState`：金币、已开垦数量、8 个地块槽位、仓库、统计、当前选中作物。
  - `plant(index, crop_id, now)`：校验空地、已开垦、金币，扣钱并记录。
  - `water(index, now)`：校验生长中、次数、冷却，累加节省时间。
  - `harvest(index, now)`：校验成熟，作物入库并清空地块。
  - `harvest_all(now)`：收获所有成熟地块，返回收获份数。
  - `sell(crop_id)`：卖出该作物全部库存，返回所得金币。
  - `sell_all()`：卖出全部库存，返回所得金币并清空仓库。
  - `warehouse_value()`：返回当前库存按卖价计算的总价值。
  - `buy_land(now)`：校验价格并解锁下一块地。
  - `remaining_seconds(index, now)`：剩余时间，成熟返回 0。
  - `progress(index, now)`：生长进度 0～1。
  - `can_water(index, now)`：是否可浇水。
- `load_state(path)` / `save_state(state, path)`：JSON 读写与容错。
- 所有“秒数”均为浮点数；界面显示时向上取整到秒。

### 11.2 界面接口

- `FarmApp(tk.Tk)`：构建界面、绑定事件、每秒调用 `refresh()`。
- `refresh()`：读取 `FarmState` 计算各块地进度，更新 Canvas、按钮状态、倒计时和窗口标题。
- 绘制函数按阶段和作物参数绘制，不引入图片资源。
- 启动时尝试 `ctypes.windll.shcore.SetProcessDpiAwareness(1)`，失败则忽略，改善高分屏显示。

## 12. 测试策略

### 12.1 核心逻辑（`test_farm.py`）

使用 `unittest`，时间以显式参数注入，不真的等待。

1. 初始状态：金币 60、4 块地已开垦、其余空地。
2. 种植：扣金币、记录时间、同一块地不能重复种、金币不足报错。
3. 生长：0%、50%、99%、100% 时的进度和剩余时间正确。
4. 浇水：每次减少总时长的 10%；最多 3 次；10 分钟冷却生效；成熟后不能浇。
5. 收获：未成熟不能收；成熟后作物进入仓库、地块清空、金币不变；累计收获次数 +1。
6. 一键收获：只收成熟地块，返回收获份数；无成熟地块时返回 0。
7. 卖出：卖出某种作物按“数量 × 卖价”加金币并清零；库存为 0 时返回 0；全部卖出合计正确并清空仓库；累计收入只在卖出时累加。
8. 开垦：价格递增、金币不足报错、开垦到 8 块后不能再开。
9. 存档往返：保存后读取，金币、地块、仓库、浇水状态、统计完全一致。
10. 离线生长：保存后模拟 2 小时再读取，作物按时间成熟。
11. 系统时间回拨：已生长时长按 0 处理，不报错。
12. 存档容错：不存在、非法 JSON、缺字段、未知作物 id 均不崩溃，并按规则降级；仓库缺失按空处理。

### 12.2 GUI 冒烟（`test_gui_smoke.py`）

- 能在不显示主循环的情况下构建窗口。
- 通过核心接口种下一块地，调用 `refresh()` 后倒计时文本存在。
- 点击地块能触发种植（直接调用事件处理函数，不模拟鼠标）。

### 12.3 人工验收

按第 13 节逐条在真实窗口中走一遍。

## 13. 验收标准

1. 双击 `run_farmer.bat` 能打开“小菜园”窗口，初始有 60 金币和 4 块可种的地。
2. 选中“小白菜”，点击空地后金币减 10，地块显示幼苗、进度条和倒计时。
3. 等待一段时间，倒计时减少、植株图形随阶段变化。
4. 点击浇水后剩余时间减少约 3 分钟，10 分钟内再次点击无效。
5. 作物成熟后地块高亮、显示“可收获”，窗口标题出现“（1 可收）”。
6. 收获后小白菜进入仓库（显示“小白菜 ×1”），金币不变，累计收获 +1，地块变回空地。
7. 在仓库点击“卖出”后获得 25 金币，仓库数量清零，累计收入 +25。
8. “一键收获”一次收完所有成熟作物并入库；“全部卖出”把库存一次卖完，金币合计正确。
9. 金币足够时开垦新地成功，价格按 200/500/1000/1800 递增，8 块后按钮消失。
10. 关掉程序一段时间再打开，作物按真实时间继续生长或已成熟，仓库内容保留。
11. 存档损坏时能正常启动并提示，不出现崩溃窗口。
12. `python test_farm.py -v` 与 `python test_gui_smoke.py -v` 全部通过。
13. 实际启动一次程序，完整走一遍“种下 → 等待/浇水 → 收获 → 卖出 → 开垦”的流程。

## 14. 风险与取舍

- Tkinter 8.6 的 emoji 支持不稳定：全部改用 Canvas 绘制，避免依赖字体。
- 高分屏下 Tkinter 可能模糊：尝试开启 DPI 感知，失败不影响功能。
- 用真实时间会让“改系统时间”影响进度：单机休闲游戏接受这一点，不做防作弊。
- 挂机游戏数值容易失衡：以“各作物单位时间收益接近”为原则，实现后可按实际手感微调。
- 没有系统托盘和通知：符合“不打扰工作”的反目标；窗口标题显示可收数量作为轻提示。
- 仓库把“收获”和“卖钱”拆成两步，可能增加操作摩擦：仓库面板常驻、提供单种卖出和全部卖出，把额外操作控制在两次点击以内。

## 15. 构建者可能自行决定的事项

- Canvas 的具体配色、圆角、字体大小和果实形状。
- 进度条和倒计时的排版细节。
- 自动保存间隔以外的实现细节（例如保存失败时静默重试）。
- 测试用例的组织方式和辅助函数。
- `README.md` 的具体措辞。
