# 局域网文件共享（shareFile）设计

日期：2026-11-11  
形态：电脑端小窗口程序 + 浏览器网页  
项目目录：`shareFile/`  
目标平台：Windows / macOS / Linux（主机端），iOS / Android（浏览器端）

## 1. 意图

在同一个 Wi-Fi 或局域网里，把文件从一台设备传到另一台设备。最常见的场景是：

- 电脑上下好的视频，想用手机看，插数据线太麻烦，微信传又慢又压缩。
- 手机拍的视频、照片，想放到电脑上存档，不想经过任何云服务。
- 同事之间临时传一个文本文件或一段素材，双方在同一网络里。

用户要的是“打开就能传、走局域网直连、尽量跑满带宽”。不需要账号、不需要互联网、不需要装手机 App。

## 2. 目标

- 电脑端运行一个小窗口程序，选定一个共享文件夹。
- 窗口显示可访问的局域网地址、二维码和 4 位口令。
- 手机或其他电脑用浏览器扫码或输入地址进入网页，输入口令后：
  - 看到共享文件夹里的文件列表（名称、大小、修改时间）。
  - 点一下下载到本机，支持大视频文件。
  - 选择本机文件上传到共享文件夹，显示进度和速度。
- 文件原样传输：不转码、不压缩、不改名（重名除外）。
- 下载支持 Range（断点续传、Safari 大文件下载更稳）。
- 主机端显示实时传输记录（方向、文件、进度、速度）。
- Windows 双击 `run_share.bat` 启动；macOS/Linux 用一条命令启动。
- 仅用 Python 3.8+ 与 Tkinter；二维码库 `segno` 是唯一第三方依赖。
- 自动化测试覆盖路径安全、认证、上传下载、Range 与 GUI 冒烟。

## 3. 非目标

- 不做互联网中转、NAT 穿透、云同步、账号体系。
- 不做 iOS/Android 原生 App，不做桌面端安装包。
- 不做网页端删除、重命名、新建文件夹、打包 zip 下载。
- 不做视频转码或在网页内播放（只提供下载）。
- 不做文本片段/剪贴板互发，只传文件。
- 不做多个共享目录、多用户权限、传输加密（TLS）。
- 不做系统托盘、开机自启、后台常驻。
- 不做传输历史持久化，关掉程序即清空。

## 4. 反目标

以下情况即使技术上可行，也算设计失败：

- 上传/下载时把整个文件读进内存，几百 MB 的视频就卡死或吃满内存。
- 同名文件被静默覆盖，用户丢数据。
- 网页暴露共享目录的绝对路径或电脑上的其他路径。
- 传输时主窗口卡住、拖动无响应。
- 文件名里有中文、空格、emoji、`#`、`?` 时下载 404 或损坏。
- 手机锁屏或切后台一次，正在传的大文件直接失败且没有任何提示。
- 共享文件夹里的隐藏文件、临时文件被列出来。
- 局域网里任何人不需要口令就能翻文件。
- 程序把“端口被占用”“防火墙拦截”“共享目录无权限”静默吞掉。

## 5. 用户已经定下的部分

- 五个平台：Windows、macOS、Linux、iOS、Android。
- 传基本文本文件和视频文件，速度优先。
- 手机端不装 App，用浏览器访问局域网地址。
- 形态是一个“主机 + 浏览器客户端”的共享目录，不是两台设备点对点对传。
- 电脑端要小窗口 + 二维码。
- 网页用 4 位口令保护。
- 用户明确接受当前设计描述。

## 6. 建造者默认决定（本设计定下的默认值）

- 技术栈：Python 3.8+、Tkinter、标准库 HTTP 服务；二维码用 `segno`。
- 不引入 Web 框架、前端构建工具、数据库。
- 主机端窗口使用中文界面；Windows 下启用 DPI 感知。
- 共享目录默认为 `shareFile/shared/`；用户可改，选择结果写入 `shareFile/config.json`。
- 运行中切换共享目录立即生效，不重启服务：已在传输中的任务按开始时的目录完成，新任务使用新目录；口令、会话、地址、二维码、端口全部保持不变。
- 默认端口 8000，被占用则依次尝试 8001–8010；仍失败则窗口显示错误，不启动服务。
- 口令每次启动随机生成 4 位数字；窗口提供“换一个口令”，旧会话立即失效。
- 网页端只读文件列表 + 下载 + 上传；删除和重命名只能在电脑上操作。
- 上传同名文件自动改名为 `name (1).ext`，绝不覆盖。
- 上传只进入共享目录根层，不支持网页端建子目录；下载递归显示子目录里的文件，路径用相对路径。
- 隐藏文件（以 `.` 开头）、`~$` 开头的 Office 临时文件、`.sharefile-tmp` 目录不列出。
- 单个上传请求不设大小上限，但必须带 `Content-Length`；分块传输（chunked）拒绝。
- 浏览器下载一律作为附件（`Content-Disposition: attachment`），不内联渲染。
- 网页上传同时最多 3 个文件，其余排队。
- 传输记录只保留最近 100 条，界面显示进行中的进度与速度。
- 主机窗口关闭即停止服务并退出，不做后台驻留。

## 7. 架构

```
┌─────────────────────────────┐
│ Tkinter 主窗口               │
│  共享目录 / 地址 / 二维码     │
│  口令 / 传输记录              │
└──────────┬──────────────────┘
           │ 同一进程，后台线程
┌──────────▼──────────────────┐
│ ThreadingHTTPServer          │
│  /            网页            │
│  /api/login   口令登录        │
│  /api/files   文件列表        │
│  /download    下载 + Range    │
│  /api/upload  流式上传        │
└──────────┬──────────────────┘
           │ 文件系统
     共享文件夹（可配置）
```

- `share_server.py`：HTTP 服务、认证、列表、上传、下载、事件队列。
- `share_core.py`：纯函数，负责文件名清洗、路径解析与越界检查、Range 解析、列表过滤、大小格式化。便于单元测试。
- `share_app.py`：Tkinter 窗口、配置读写、网卡地址枚举、二维码、启动/停止服务。
- `web/`：`index.html`、`app.js`、`style.css`，启动时读入内存。
- 服务在后台线程运行；GUI 每 200 ms 从 `queue.Queue` 取传输事件刷新列表。

## 8. 主机窗口

窗口尺寸约 560×760，最小尺寸不小于内容所需宽度；布局全部用自然宽度与权重，不用固定字符宽度硬挤中文。

自上而下：

1. **共享文件夹**：路径显示、`选择…`、`打开`。
2. **访问地址**：网卡地址下拉框（多网卡时可选），显示 `http://<ip>:<port>/`，`复制` 按钮。
3. **二维码**：220×220 白色画布，黑模块，四周留 4 模块静区。二维码内容只有访问地址，不含口令。
4. **口令**：4 位数字大号显示，`换一个口令`。
5. **传输记录**：`方向 / 文件 / 大小 / 进度 / 速度`；进行中原地刷新，完成后保留；最多 100 条。
6. **状态栏**：`运行中 · 端口 8000` 或具体错误。

细节：

- Windows 启动时调用 `SetProcessDpiAwareness(1)`；非 Windows 跳过。布局按真实 DPI 校验。
- 多网卡时优先展示 `192.168.*`、`10.*`、`172.16–31.*` 的地址，下拉切换后二维码重画。
- `segno` 未安装时，二维码区域显示文字提示与安装命令，其余功能不受影响。
- 端口全部被占用或绑定失败：状态栏红字提示，传输区不可用。
- 共享目录可读但不可写：浏览和下载照常，只禁用上传，状态栏标注“只读”。
- 共享目录完全不可读：状态栏红字提示，浏览、下载、上传都不可用。
- 关闭窗口：`server.shutdown()`，后台线程退出，进程结束。

## 9. 网页端

单页应用，原生 JavaScript，无框架，移动端优先。

**登录视图**

- 4 位数字输入框（`inputmode="numeric"`），回车提交，提交中禁用按钮。
- 错误提示：口令错误、尝试过多等待 N 秒、网络错误。
- 登录成功后 Cookie 保持 12 小时，刷新页面不用重新输入。

**文件视图**

- 顶栏：共享目录名（只显示文件夹名，不显示绝对路径）、`刷新`、`上传`。
- 文件列表：文件名（可换行省略）、大小、修改时间、下载按钮。
  - 目录按名称排序，目录内文件排在前面（列表是递归扁平结构时，按相对路径排序）。
  - 用 `textContent` 渲染文件名，禁止拼 HTML。
- 空目录显示“共享文件夹还是空的，点上传或把文件拖进来”。
- 上传：`<input type="file" multiple>` + 拖拽区域；手机端点击后可选照片/视频/文件。
  - 同时最多 3 个并发；每个文件一条进度条、速度、取消按钮。
  - 上传完成立即刷新列表；上传中暂停自动刷新。
- 下载：`<a href="/download?path=...">`，服务端强制附件并给出正确文件名。
- 页面每 10 秒自动刷新列表（标签页可见且无上传任务时）。
- 样式：系统字体，浅色/深色跟随 `prefers-color-scheme`；触控目标不小于 44px。

## 10. HTTP 接口

所有 API 返回 JSON；错误格式 `{"error": "..."}`，并带合适的 HTTP 状态码。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 返回网页（未登录也返回，由前端显示登录视图） |
| GET | `/static/<file>` | `app.js`、`style.css` |
| POST | `/api/login` | 请求 `{"pin":"1234"}`，成功 `{"ok":true}` 并设置 Cookie |
| POST | `/api/logout` | 清除 Cookie |
| GET | `/api/session` | `{"authed":true/false}` |
| GET | `/api/files` | `{"files":[{"path":"a/b.mp4","name":"b.mp4","size":123,"mtime":1700000000}]}` |
| GET | `/download?path=<相对路径>` | 下载；支持 Range；无 Cookie 返回 401 |
| PUT | `/api/upload?name=<文件名>` | 原始请求体即文件内容；必须带 `Content-Length` |

上传响应：`201 {"name":"实际保存名","size":123}`；失败返回 4xx/5xx 与错误信息。

### 10.1 下载

- 路径参数为共享目录内的相对路径，统一用 `/` 分隔。
- `Content-Type: application/octet-stream`，`X-Content-Type-Options: nosniff`。
- `Content-Disposition: attachment; filename*=UTF-8''<百分号编码>`；无中文时也带 ASCII `filename`。
- 支持 `Range: bytes=start-end`、`bytes=start-`、`bytes=-suffix`，返回 `206` 与 `Content-Range`。
- 多段 Range、语法错误返回 `416`，附 `Content-Range: bytes */<size>`。
- 实现优先用 `socket.sendfile`（Windows 走 TransmitFile），不可用时 1 MiB 分块写。

### 10.2 上传

- 请求体按 `Content-Length` 精确读取，1 MiB 一块写入 `.sharefile-tmp/` 下的临时文件。
- 客户端断开或写入失败：删除临时文件，不留下半截文件。
- 完成后按清洗后的文件名原子 `os.replace` 到共享目录根层。
- 文件名清洗：去掉路径部分；替换 Windows 非法字符 `<>:"/\|?*` 和控制字符；去掉首尾空格与结尾的点；空名或保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1–9`、`LPT1–9`）加前缀 `file-`；限制长度 200 字符。
- 重名：`name.ext` → `name (1).ext` → `name (2).ext`，逐个尝试，以独占创建避免覆盖。
- `Content-Length` 缺失或为 0：`411` / `400`。
- 上传成功、失败、断开都向 GUI 事件队列发送事件。

## 11. 认证与安全

- 口令：`secrets` 生成 4 位十进制（允许前导 0），每次启动重新生成。
- 会话：登录成功后生成 32 字节随机 token，`Set-Cookie: sf_session=<token>; HttpOnly; SameSite=Lax; Path=/; Max-Age=43200`；token 存内存集合，换口令或退出时清空。
- 未认证访问 `/api/files`、`/download`、`/api/upload` 返回 401。
- 暴力尝试：同一 IP 连续 5 次错误后锁定 60 秒，返回 429 与剩余秒数；正确登录后清零。
- 变更类请求要求 `X-Requested-With: shareFile`，配合 SameSite 降低 CSRF 风险。
- 路径安全：只允许共享目录内路径；拒绝绝对路径、盘符、`..`、NUL；`realpath` 后必须仍在共享目录内；符号链接只有在目标仍位于共享目录内时才允许；列表跳过符号链接目录。
- 网页响应带 `Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`，并设置 `Referrer-Policy: no-referrer`。
- 程序只用于可信局域网；4 位口令是轻量防护，不是公网安全方案，README 明确说明。

## 12. 性能设计

目标是让局域网带宽成为瓶颈，而不是程序：

- 文件传输全程流式，8–64 MB 级内存占用不随文件大小增长。
- 下载优先 `sendfile`；上传/回退路径用 1 MiB 读写缓冲。
- 连接设置 `TCP_NODELAY`；`ThreadingHTTPServer` 每连接一线程，允许多人同时下载。
- 不压缩、不加密、不做哈希校验（局域网内 TCP 已保证完整性）。
- 关闭 `BaseHTTPRequestHandler` 的逐请求日志；只向 GUI 队列发轻量事件，进度最多每 250 ms 一次，避免拖慢传输。
- 资源文件启动时读入内存；列表缓存 1 秒，避免多人反复刷新时重复扫描目录。
- README 给出预期：千兆有线约 110 MB/s，Wi-Fi 取决于路由器与信号；不要用“理论峰值”做验收。

## 14. 错误处理

- 端口占用：自动尝试后续端口；全部失败则提示，不启动。
- 共享目录不存在：尝试创建；创建失败则浏览、下载、上传都不可用。
- 共享目录可读但不可写：列表与下载照常，只禁用上传，窗口状态栏标注“只读”；网页上传按钮置灰并提示。
- 磁盘写满（`OSError` / `ENOSPC`）：删除临时文件，返回 507，网页显示“磁盘空间不足”。
- 文件名非法：清洗后保存，响应里返回实际名称，网页刷新后显示真实文件名。
- 客户端中断：捕获 `ConnectionError`/`BrokenPipeError`，标记失败，不影响其他传输。
- 列表里遇到无权限文件：跳过并在主机状态栏计数提示，不中断整个列表。
- 浏览器 Cookie 失效：API 返回 401，前端切回登录视图。

## 16. 验收标准

1. Windows 双击 `run_share.bat`（或 `python share_app.py`）打开窗口，显示地址、二维码、口令，状态为运行中。
2. 手机与电脑同一 Wi-Fi：扫码 → 输入口令 → 看到电脑共享目录里的文件 → 下载一段视频，能正常播放。
3. 手机选一个视频/照片上传 → 网页显示进度和速度 → 电脑共享目录出现文件，大小一致。
4. 另一台电脑用浏览器同样可访问、上传、下载。
5. 传 1 GB 级文件时内存占用平稳，窗口不卡；速度接近局域网带宽（有线千兆目标 ≥ 80 MB/s，Wi-Fi 不作硬指标）。
6. 断网/取消后重试可正常继续（重新上传或 Range 下载）。
7. 全量测试通过，Python 3.8.3 下可运行。

## 17. 运行方式

- Windows：安装 Python 3.8+，`pip install -r requirements.txt`，双击 `run_share.bat`。
- macOS/Linux：`pip3 install -r requirements.txt && ./run_share.sh`；Linux 若缺 Tkinter，先装 `python3-tk`。
- 首次启动 Windows 防火墙可能弹窗，需允许“专用网络”访问。
- 手机与主机必须在同一局域网；访客 Wi-Fi 开启“客户端隔离”时无法互访，这属于网络限制。
