# 地下城跑团游戏（自包含网页版）设计文档

- 日期：2026-11-16
- 状态：待批准
- 来源需求：`CLAUDE.md`（《地下城跑团游戏 DM》v0.2）

## 1. 意图与原因

把 `CLAUDE.md` 里写给"大模型当 DM"的跑团规则，实现成一个**真实的、可分享给别人玩的自包含网页游戏**。

原设计依赖大模型临场生成剧情，但用户明确要求"能发给别人、时刻保证能玩能跑"。AI 驱动版需要接口和 key、别人拿到手不一定能跑。因此改为**完全自包含**：规则用代码实现，剧情文案预先写好随机抽取，离线可玩、双击即玩。

## 2. 目标（要做的）

- 一个自包含网页游戏：纯 HTML + CSS + 原生 JS，无框架、无联网、无构建步骤、无外部依赖。
- 分享形态：默认打包成**单个 HTML 文件**（代码/样式/文案全内联），一个文件即可发送、双击即玩；内容过大时退化为 index.html + game.js + style.css 三件套，但保持离线可用。
- 暗黑哥特风格：深色底、火把暖光/血红点缀、氛围化排版与转场，不用外部图片（用 CSS + emoji/字符画营造场景，保证离线也有画面感）。
- 移动端自适应。
- 完整实现 `CLAUDE.md` 全部游戏规则（战斗、探索判定、角色、怪物、奖励、互动、胜负）。
- 范围：**20 层全做**——20 个怪物（第 20 层为最终 Boss），每层有可探索的互动元素。

## 3. 非目标（明确不做的）

- 账号系统、云端存档、多人在线、任何后端。
- 接入真实 LLM / 联网 API。
- 外部美术资源、音效（除非后续要求）。
- 复杂动画 / 3D。

## 4. 反目标（出现即算失败）

- 页面打不开、报错、卡死、流程走不通。
- 战斗数值算错（HP、法力、暴击、伤害）。
- 探索判定与规则不符。
- 别人拿到文件打不开或不能玩。
- 依赖联网资源导致离线不可用。

## 5. 约束

- 纯前端、无外部依赖（不引用 CDN，离线可用）。
- 单文件优先；可拆三件套但仍离线。
- 移动端自适应。
- 数值逻辑必须可测试（核心规则抽成纯函数）。

## 6. 用户已定的"怎么做"（照实记录）

- 网页 / 自包含单文件 / 暗黑哥特风格 / 发给别人可玩 / **20 层全做** / 首要保证"能玩能跑"。

## 7. 游戏规则（严格照 CLAUDE.md 实现）

### 7.1 角色

**法师** — HP 100，法力 100，攻 5，防 5，智力 8
- 火球术：耗法力 10，伤害 30
- 法力护盾：耗法力 20，免疫伤害 3 回合
- 奥术智慧：免费，回 30 法力
- 暴风雪：耗法力 30，对 100 米内所有敌人 20 伤害（对当前单体怪 = 20）

**战士** — HP 200，法力 50，攻 15，防 10，智力 5
- 格挡反击：耗法力 10，格挡敌方下一次伤害并造成等量反伤
- 怒吼：耗法力 20，下一次攻击造成 3× 伤害
- 旋风斩：耗法力 20，对 10 米内敌人 30 伤害（对单体 = 30）
- 裁决：耗法力 30，直接处决 HP 低于 20% 的敌人

### 7.2 战斗规则

- 回合制，**玩家先手**。
- 伤害 = 攻击方攻击力 − 防守方防御力（**最低为 1**，避免 0/负值）。
- 玩家所有攻击方式（普攻 + 技能）都有 **10% 概率暴击 = 3× 伤害**。
- 战斗中玩家**每回合法力 +5**。
- 任一方 HP ≤ 0 战斗结束；HP ≤ 0 一方为败方。
- 战斗结束后**回满玩家法力**；HP 部分恢复（见 7.10）。
- 玩家每回合可选：普通攻击，或一个**已掌握且法力足够**的技能。
- 普通攻击伤害 = 玩家攻击力。
- 玩家 HP ≤ 0 → 角色死亡 → 失败结局（可重开选角）。

### 7.3 探索判定

- 触发"探索/检查/检视/探查"类动作时：生成**难度值 X ∈ [9,13]**（整数）。
- 玩家掷 d6 得 R（1-6）。**探索点 = R + 智力**。
- 探索点 > X → **探索成功**（奖励：小量 HP/法力，或装备/属性，或揭示隐藏）。
- 否则 → **探索失败**（惩罚：少量伤害，或触发一个怪物）。

### 7.4 怪物

- 每个怪物：HP、攻击力、防御力、**一个技能**（伤害约 2× 攻击力，**50% 概率发动**）。
- 每层 1 个，共 20 个（第 20 层为最终 Boss，数值与技能最强）。
- 数值随层数递增（建造者设计一条平滑曲线，确保前易后难）。
- 怪物回合：50% 概率用技能（约 2× 攻），否则普通攻击；同样受防御减伤。
- **打败怪物随机奖励**：某属性提升，或一件装备/武器（见 7.5）。

### 7.5 奖励与装备（建造者决定，已定默认）

- 奖励二选一（随机）：
  a) **属性成长**：随机一项永久提升——攻击力 +1~3 / 防御力 +1~2 / HP 上限 +10~20（并回满）/ 智力 +1。
  b) **装备**：从该层装备池取一件。
- 装备槽位（建造者决定）：**武器（+攻）/ 护甲（+防）/ 饰品（+智力或回法）**，每槽同时持一件；获得同槽新装备时，数值更高则替换，否则丢弃。装备加成并入角色面板实时显示。
- 面板实时显示：当前 HP/法力、攻/防/智力、当前装备、当前层数。

### 7.6 互动元素（每层随机出现若干，建造者实现）

- **箱子**：打开得奖励；小概率是陷阱（小伤害）。
- **谜题机关**：破解成功得奖励，失败少量伤害（简单判定，如二选一或数字题）。
- **猜拳石像**：石头剪刀布，赢奖励、输小惩罚。
- **神秘祭坛**（自建）：祈祷回法力，或冒风险换大奖励。
- **陷阱通道**（自建）：小概率触发伤害，可提前"探查"规避。

### 7.7 层与流程

- 开场：介绍目标 → 选角色（显示属性）→ 进入第 1 层。
- 每层循环：描述房间 → 给选项（可探索要素 + 遭遇怪 + "说出你想做什么"）→ **1-2 次探索后必遇怪** → 战斗 → 胜利 → 进入下一层。
- 第 20 层：打败最终 Boss → 获得**「复苏之心」** → **胜利结局**。
- 死亡：HP ≤ 0 → 失败结局 → 可重开。

### 7.8 场景画面

- 原规则每轮输出 `**场景**：![Image](pollinations URL)`。
- **建造者决定**：默认用 **CSS 渐变 + emoji/字符画** 营造每层场景氛围（不依赖外部图床，保证离线可用、"确保能玩"）。可选：在线时尝试加载 pollinations 图，失败自动回退 CSS 场景；默认不依赖联网。

### 7.10 HP 恢复经济（用户已定：选项 2——部分恢复，保留紧张感、仍能通关）

- **每进入新的一层**（即上一层怪物被击败后）：HP 回补**上限的 25%**。
- **探索成功**：额外回少量 HP（约 +10~15）。
- **神秘祭坛祈祷**：回法力；或冒风险换较多 HP 回复。
- 击败怪物获得"HP 上限"类奖励时：上限提升并**回满 HP**。
- **不自动回满**，保留跑团紧张感，但数值曲线要保证"正常发挥可通关 20 层"（建造者据此调平衡，并纳入验证）。

### 7.9 状态与 UI

- 游戏状态用 JS 对象维护：角色、HP、法力、属性、装备、当前层、buff 状态。
- buff 状态管理：法力护盾剩余回合、格挡反击待发、怒吼待发。
- 战斗日志：滚动显示每回合发生的事（谁做了什么、伤害/暴击/法力变化），数值清晰可见。
- 每步给玩家**有序号**的行动选项 + 末尾"说出你想做什么"（自由输入，给出合理反应）。

## 9. 验证标准（硬性）

- 核心数值逻辑（伤害、暴击、法力、探索判定、buff）抽成**纯函数**并配单元测试。
- 完整流程手测：选角 → 探索 → 遇怪 → 战斗（含技能/buff/暴击）→ 掉落 → 逐层推进 → 20 层 Boss → 胜利结局；以及死亡/重开路径。
- 边界：HP 归零、法力不足、暴击触发、buff 到期、装备替换。
- 交付前在真实浏览器（桌面 + 手机视口）离线跑通，确认"能玩能跑"。
