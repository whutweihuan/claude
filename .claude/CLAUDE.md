## Git 卫生

- `.gitignore` 只对未跟踪文件生效。已经被跟踪的 `__pycache__`、`save.json` 等要用 `git rm --cached` 移出索引，磁盘文件保留。
- 通用忽略规则放根目录 `.gitignore`，项目特有的放子目录（例如 `farmer/.gitignore`）。
- 提交前确认只暂存目标文件；工作区里其他项目的未提交改动不要顺手带进去。

## 技能与验证

- 修 UI/交互 bug 也走 systematic-debugging：先量实际控件尺寸和文字 bbox，再改布局；不要凭“看起来差不多”直接调参数。
- 声称修好之前必须跑完整测试套件，并尽量模拟真实启动路径（包括 DPI、真实 save 路径、主窗口 mainloop）。

## 长任务与上下文：先打通最小可运行路径

**症状**（demo_word 地下城，2026-11-17）：约 900 行代码、38 个单测全绿、计划完成 5/8，但打开 `index.html` 后所有选项按钮都点不动，游戏停在第 1 层；累计约 3.5 小时、1460 万输入 token。

**根因**：

- 计划按技术层切：纯函数（T1–T4）→ UI 骨架（T5）→ 接线（T6/T7）→ 全流程验证（T8）。集成放在最后，而 T5 被明确允许使用 inert 按钮（裁决 C25）和占位路径（C27）。
- “能玩”没有进入完成定义。验收依赖任务 8 的真人浏览器手测，子代理用核心逻辑模拟替代（C29），正好绕开唯一出问题的 UI 层。
- 上下文 131k，规格 + 计划 + 裁决共 58KB（与代码量相当）。单次会话出现 17 次续接、4 次输出截断、25 万字符摘要重新注入；状态丢失后重跑测试、回填账本，提交顺序都乱了（T6 抢在 T5 前）。
- 计划 753 行且内嵌完整实现，每个子代理都要读全量规格和计划。

**做法**：

1. **第一个任务永远是 walking skeleton**：一条端到端路径（启动 → 一次交互 → 状态变化 → 结束）跑通后再扩展。Web 项目必须“点得动”，CLI 项目必须“跑得出结果”，Tk 项目必须“真实主窗口能操作”。
2. **完成定义写成可执行断言**：单测 + 端到端冒烟（headless 浏览器断言 DOM 状态变化 / CLI 断言输出）。不接受“任务清单打勾”或“人工手测待定”。
3. **按垂直切片拆任务**，不要按技术层拆；每片自带入口、交互和测试。
4. **计划只写接口、验收和关键数值**，不嵌完整实现；子代理只读自己那一节，不读整份计划。
5. **长会话不可靠**：每个切片维护一份 10 行状态文件（做到哪 / 下一步 / 验证命令）。同一会话续接超过 3 次或触发输出截断，立即收窄任务或换会话，不要硬扛。
6. **临时验证脚本一旦抓到问题，立即转成仓库内的回归测试**，不要当 scratch 清掉。
7. 判断“是否完成”时先问：用户拿到手会做的第一个动作是什么？那个动作有没有被自动化验证过？
