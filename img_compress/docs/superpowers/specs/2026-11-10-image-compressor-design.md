# 图片压缩工具设计

日期：2026-11-10  
目标平台：Windows 10/11  
形态：本地桌面程序（Python + Tkinter），附命令行入口

## 1. 意图

用户需要在 Windows 电脑上压缩手机照片、网页素材、毕业长图和一寸照片等图片。
核心诉求是：用固定档位选择压缩强度，既能处理单张图片，也能批量处理；
默认保持原格式，也可以转换成体积更小的格式；尺寸调整是可选项。
所有处理都在本机完成，不上传图片。

## 2. 目标

- 提供图形界面，支持通过按钮选择单张、多张图片和整个文件夹。
- 提供四个压缩档位：轻度、标准、强力、极限；默认标准。
- 默认保持输入格式，并允许统一输出为 JPG、WebP 或 PNG。
- 可选“限制长边”缩放，只缩小、不放大，保持宽高比。
- 输出到指定文件夹，不覆盖原图；批量处理中单张失败不影响其他图片。
- 支持 JPG/JPEG、PNG、WebP、BMP、TIFF、HEIC/HEIF 静态图片和单帧 GIF。
- 提供 `compress.py` 命令行入口，便于脚本化使用。
- 用自动化测试覆盖压缩档位、格式转换、缩放、透明通道、输出命名和错误处理。

## 3. 非目标

- 不做证件照裁剪、换背景、排版或打印尺寸换算。
- 不处理动画 GIF/WebP；检测到多帧时跳过并报告。
- 不提供“目标文件大小”自动搜索模式。
- 不上传云端、不做账号、不做图片编辑。
- 不覆盖原始文件。
- 不实现 Windows 资源管理器拖放；文件通过按钮选择，避免引入额外 GUI 依赖。
- 不保证所有图片压缩后一定更小；仅在同格式、未实际缩放时回退为原图并如实说明。

## 4. 关键决定

以下为实现层面的默认决定，除非用户另行指定：

- 沿用现有 `img_add` 项目的技术风格：Python 3.8+、Pillow、Tkinter、`run_gui.bat`。
- 新建独立目录 `img_compress/`，不改动现有图片拼接工具。
- HEIC 读写使用 `pillow-heif`；依赖写入 `requirements.txt`。
- 输出文件命名：`<原文件名>_compressed.<输出扩展名>`；重名时追加 `_1`、`_2`。
- 输出目录默认：第一张图片所在目录下的 `compressed/`。
- 压缩时应用 EXIF 方向后移除 EXIF 等元数据；保留 ICC 色彩配置以减少偏色。
- 透明图片转 JPG/HEIC 时用白色铺底；转 WebP/PNG 时保留透明。
- 同一格式、未实际缩放且处理结果反而更大时，复制原图作为输出并标记“已保留原图”。
  “同一格式”按规范化后的编码格式判断，不看扩展名大小写；“未实际缩放”指输出尺寸与原图一致，
  而不是指用户是否勾选了限制长边（例如长边设为 4000、原图仅 1200 时不发生缩放）。
- 用户明确选择转换格式或确实发生缩放时，即使结果更大也输出处理后的文件，并在状态中说明；
  此时不复制原图，以免输出格式或尺寸与用户选择不符。

## 5. 压缩档位

档位只控制画质/调色板，不自动改变尺寸；尺寸由“限制长边”单独控制。

| 档位 | JPEG 质量 | WebP 质量 | HEIC 质量 | PNG/GIF 颜色数 |
| --- | --- | --- | --- | --- |
| 轻度 | 90 | 85 | 85 | 不量化（PNG 无损优化；GIF 最多 256 色） |
| 标准 | 75 | 75 | 70 | 256 色 |
| 强力 | 55 | 55 | 50 | 128 色 |
| 极限 | 35 | 35 | 30 | 64 色 |

补充规则：

- JPEG 使用 `optimize=True`；轻度使用 4:4:4 色度采样，其余档位使用 4:2:0。
- WebP 使用 `method=6`，以换取更好的压缩率。
- PNG 量化使用 Pillow 的 FASTOCTREE，支持保留透明通道；量化失败时退回无损优化。
- TIFF 使用 deflate 压缩；BMP 本身无压缩，保持原格式时文件通常不会变小。
- 静态 GIF 按档位减少调色板颜色；多帧动图跳过。
- HEIC 通过 pillow-heif 读取并写回；编码器不可用时给出明确错误和安装提示。

## 6. 图形界面

主窗口标题“图片压缩工具”，尺寸约 900×680，布局沿用现有拼接工具的风格。

- 文件列表：Treeview，列为“文件 / 原始大小 / 压缩后 / 状态”；支持多选删除。
- 文件操作：添加图片、添加文件夹（可选包含子文件夹）、删除选中、清空。
- 压缩设置：
  - 压缩档位下拉框（轻度/标准/强力/极限），默认“标准”。
  - 输出格式下拉框（保持原格式/JPG/WebP/PNG），默认“保持原格式”。
  - “限制长边”复选框 + 像素输入框，默认关闭，默认值 1920。
  - 输出文件夹输入框 +“浏览...”。
- 底部：开始压缩按钮、进度条、状态文本。
- 压缩在后台线程执行，界面不冻结；完成后弹窗汇总成功数、失败数、总节省体积。
- 双击或点击结果列不打开文件；保持简单。
- 若未添加图片、输出目录为空、长边参数非法，给出可读的中文提示。

## 7. 命令行

```bash
python compress.py <文件或文件夹...> [-l 档位] [-o 输出目录] [-f 格式] [--max-size 长边] [-r]
```

- `-l/--level`：`light|standard|strong|extreme`，默认 `standard`。
- `-o/--output`：输出目录，默认第一个输入所在目录的 `compressed/`。
- `-f/--format`：`keep|jpg|webp|png`，默认 `keep`。
- `--max-size`：限制长边像素，只缩小不放大。
- `-r/--recursive`：文件夹输入包含子目录。
- 单张失败输出警告并继续；至少成功处理一张时进程返回 0，全部失败返回 1。

## 8. 结构与实现

```
img_compress/
  compress.py          核心压缩逻辑 + CLI
  compress_gui.py      Tkinter 图形界面
  test_compress.py     自动化测试
  run_gui.bat          Windows 双击启动
  requirements.txt     Pillow、pillow-heif
  README.md            使用说明
  docs/superpowers/specs/2026-11-10-image-compressor-design.md
```

核心接口：

- `expand_inputs(paths, recursive)`：展开文件、目录，按自然顺序排序并去重。
- `compress_image(src, dst_dir, level, output_format, max_edge)`：处理单张，返回结果对象。
- `compress_files(...)`：批量处理，返回汇总，供 GUI/CLI 共用。
- `unique_output_path(...)`：生成不冲突的输出路径。

输出格式解析：

- `keep` 使用输入文件的可写格式；`.jpeg` 统一写成 `.jpg`。
- 不支持的输入扩展名交给 Pillow 尝试，失败则记录并跳过。
- 动画图片检测 `n_frames > 1` 后跳过，不输出半成品。

## 9. 边界与错误处理

- 单张失败记录原因，继续处理其他文件，最终汇总。
- 输出目录不存在时自动创建；创建失败则整体报错。
- 源文件与目标路径相同时绝不覆盖；命名器保证追加后缀。
- 透明图转不支持透明的格式时白底合成。
- 图片被占用或权限不足时给出路径和错误原因。
- HEIC 依赖缺失时提示：`python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple pillow-heif==0.18.0`。
- 极限压缩可能产生明显画质损失，界面在档位旁提示“体积优先”。

## 10. 验收标准

1. 选择单张 JPG，标准档压缩后文件小于原图（测试用噪声图）。
2. 批量添加多种格式，成功输出到新建目录，文件名带 `_compressed`。
3. 保持原格式时，PNG 仍是 PNG、WebP 仍是 WebP、HEIC 仍是 HEIC。
4. 选择 JPG/WebP/PNG 时扩展名与编码一致。
5. 透明 PNG 转 WebP/PNG 后透明区域仍透明；转 JPG 后为白色。
6. 设置长边 800 后，输出图片长边为 800，宽高比不变，且不放大。
7. 同一输入重复压缩产生 `_1`、`_2` 等不冲突文件名，原图不变。
8. 动画 GIF 被跳过并给出原因，其余图片继续。
9. 全部失败时 CLI 返回 1；部分失败时其余图片仍成功。
10. `python test_compress.py -v` 全部通过。

## 11. 测试策略

- 使用 Pillow 在临时目录生成可重复的测试图片，不依赖外部素材。
- 核心逻辑测试：档位映射、尺寸、格式、透明、命名冲突、原图保留、动画跳过。
- HEIC 测试在 pillow-heif 可用时执行；缺失时明确跳过，不伪装通过。
- GUI 做最小冒烟测试：能构建窗口、添加文件、校验参数；主要逻辑由核心测试覆盖。
- 完成后实际启动一次 GUI 并压缩一张样例图，确认进度和汇总正常。

## 12. 风险与取舍

- HEIC 依赖原生库；若安装失败，HEIC 功能不可用，但其他格式不受影响。
- PNG 强压依赖调色板量化，照片类 PNG 可能出现色带；界面档位名称和提示会说明。
- BMP 保持原格式不会明显变小；用户可主动选择 JPG/WebP。
- 压缩质量是主观的，档位参数提供合理默认值，不做逐图自适应。
