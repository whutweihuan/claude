# 勇士冒险 GUI 窗口界面设计（鼠标驱动）

日期：2026-11-13  
关联：终端版设计 `2026-11-13-warrior-roguelike-design.md`（规则权威，本文件只覆盖界面形态）  
形态：Windows 桌面 Tkinter 窗口，双击/`python main.py` 默认进窗口；纯标准库，无图片、无第三方、无音效。

## 1. 意图与原因

终端版靠编号+键盘命令操作，玩家反馈繁琐。本功能给同一个游戏加一层鼠标驱动的图形界面：点卡牌、点敌人、点按钮完成全部操作，键盘一个键都不按。游戏规则、数值、存档格式完全不变。

## 2. 用户已经定下的部分

- 加入简单 UI 和鼠标控制，替代按键操作（用户原话）。
- 双击打开窗口就能玩，风格像 farmer/milkCow（用户确认"对"）。
- 视觉简单朴素：纯 Tkinter 原生控件 + Canvas 血条，不自绘花哨元素（用户原话"简单朴素即可"）。
- 终端版去留用户未表态——本设计决定保留为 `--text` 兜底模式（写在此处为设计者决定，非用户要求）。

## 3. 目标

- 完整游戏循环全部窗口化：标题（种子输入框+开始按钮）→ 地图 → 各类节点 → 战斗 → 结算屏（战绩统计+再来一局/离开按钮）。
- 战斗鼠标交互：敌人一排（名字、Canvas 血条、血量数字、意图文字、状态小字）；手牌一排卡片按钮（名称+费用+效果文本，费用不足置灰）；点攻击牌进入"选目标"态（敌人按钮高亮+出现"取消"按钮），点敌人出手；结束回合/药水/详情为固定按钮；战斗日志滚动文本框。
- 地图屏：按层竖排的节点按钮（图例字符+名称），仅当前可达节点可点。
- 火堆/事件/商店/宝箱/奖励：文本区+按钮组，与终端版选项一一对应，无新增规则。
- DPI 纪律全部落地（见 5），并有一条子进程真实 DPI 布局回归测试（沿用 farmer 验证过的模式）。
- 现有 98 个测试保持全绿；`core.py`/`content.py`/`records.py` 逻辑零改动（允许新增纯查询辅助函数）。

## 4. 非目标

- 不做拖拽出牌、动画、图片、音效、主题、字体设置、全屏缩放适配（DPI 自动缩放除外）。
- 不做键盘快捷键（Enter/Esc 保留 Tk 原生行为即可）。
- 不改游戏数值、掉落、地图规则、存档结构。
- 不做多窗口、多存档、对局中续档（沿用终端版：退出即弃局，战绩除外）。

## 5. 布局与 DPI 纪律（来自仓库 .claude/CLAUDE.md，必须执行）

1. `main()` 走 GUI 路径时调用 `SetProcessDpiAwareness(1)`，与 farmer 相同。
2. 布局测试必须在**子进程**里先设同样 DPI 再建 Tk，禁止同进程直接实例化测布局。
3. 中文标签一律自然宽度 + grid `weight`，不用固定 `width=N` 字符数硬挤。
4. 面板若 `pack_propagate(False)`，测试逐个断言子控件 `winfo_reqwidth() <= winfo_width()`。
5. Canvas 文字用 `anchor` 加正边距，防顶部裁切。
6. 窗口基准 1000×660，`minsize` 不低于布局需求宽；2.33 缩放下文字不裁切为验收断言。
7. 卡片按钮文本两行（名称费用 / 效果摘要），效果长句用 `wraplength` 换行，不截断。

## 6. 结构

```
warrior/
  main.py          # 默认启动 GUI；--text 走终端会话（现有逻辑保留）
  gui.py           # 新增：WarriorGUI 全部窗口逻辑（只消费 core 公开接口）
  test_gui.py      # 新增：布局回归（子进程 DPI）+ 无显示环境的回调级单测
```

- `gui.py` 不实现任何游戏规则：战斗状态从 `combat.snapshot()` 读，操作经 `play_card/end_turn/buy/...` 走，与终端 UI 同一接口面。
- 无显示环境（CI）时 `test_gui.py` 的窗口测试 skip，回调级测试仍可跑（以 `tkinter.Tk()` 可用性判断）。

## 7. 风险

- Tk 无真实 mainloop 的测试只能驱动回调，无法验证事件循环行为 → 用子进程冒烟 + 人工验收清单兜底。
- 手牌最多 10+ 张时一排按钮会溢出 → 计划规定手牌区用可换行的 Frame 流式布局，测试断言 12 张手牌时区域总宽不超窗口。
