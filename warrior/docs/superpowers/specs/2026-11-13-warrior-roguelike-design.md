# 勇士冒险（终端 Roguelike 卡牌游戏）设计

日期：2026-11-13  
目标平台：Windows 10/11 控制台（cmd / Windows Terminal）  
形态：本地终端程序（Python 3.8+，仅标准库），`python main.py` 即玩  
项目目录：`warrior/`

## 1. 意图与原因

用户想要一个纯文字的 roguelike 卡牌游戏：勇士从山脚出发，一路打怪、捡装备、做抉择，最终在地图顶端打倒魔王；死了就重开，靠每一局的不同构筑和取舍获得乐趣。

核心乐趣链条：

- 战斗手感优先：像《杀戮尖塔》那样回合制出牌，敌人意图可见，每一张牌都要做取舍。
- 成长不靠等级：变强只靠路上获得的武器、防具、遗物、新牌，以及火堆的强化选择。
- roguelike 的路线抉择：分支地图决定这局遇到什么——贪奖励走精英，还是求稳睡火堆。
- 单局十几分钟，输了随时重开。

我们押注的头号标准是"战斗手感 + roguelike 选择的取舍感"；事件文本和数值表够用即可。

## 2. 用户已经定下的部分

以下内容来自用户的明确表述或逐条确认，不是建造者的猜测：

- 类型：roguelike，勇士冒险打倒魔王。
- 战斗：类杀戮尖塔的回合制出牌（非自动结算）。
- 要素齐全：火堆、随机事件、普通战斗、精英战斗、boss 战斗、商店、武器、防具、遗物。
- **没有等级/经验升级系统**：角色无等级，成长全部来自装备、遗物、卡牌与火堆强化。
- 交互形态：纯文字终端交互，input() 菜单驱动，不做 GUI。
- 篇幅：一张 15~20 个节点的分支地图，中途 1~2 场精英，走到头一场魔王战，打完即通关，单局十几分钟。
- 火堆二选一：睡觉回 30% 血，或锻造强化。
- 死亡即本局结束重开。

## 3. 目标

- 可一局通关的完整循环：初始卡组 → 走地图 → 战斗/事件/商店/火堆 → 魔王战 → 胜利结算 → 可再来一局。
- 卡牌战斗核心：能量、手牌、抽/弃/洗堆、格挡、意图显示、多敌人目标选择。
- 一批可用的内容：约 30 张卡牌池、5~8 件武器、5~8 件防具、约 20 个遗物、5~6 种药水、8~10 个随机事件、10 种左右敌人（含 2 精英、1 魔王）。
- 分支地图随机生成，每次开局都不同，但保证结构上可通关（有火堆、有商店、精英数量固定）。
- 战绩元数据持久化（局数、胜场、最远深度、击杀统计），存档损坏不崩溃、不污染。
- 核心逻辑全标准库、确定性可测试（注入随机种子即可复现整局）。
- 自动化测试覆盖战斗结算、地图生成、存档安全，并有一次模拟整局的自走冒烟。

## 4. 非目标

- 不做多职业/多角色：只有"勇士"一个初始配置。
- 不做卡牌收集式元进度（解锁牌、解锁遗物）：所有内容开局即在池子里随机出现。
- 不做中途存读档：一局内退出程序即放弃本局（战绩记录除外）。
- 不做成就、任务、剧情线、音效。
- 不做联机、排行榜。
- 不做第三方依赖、图片素材。
- 不做诅咒牌/复杂异常状态体系（力量、易伤两类简单状态够用，其余状态不做；毒作为药水/敌人专属的唯一例外，见 6.2/6.11）。
- 不做手机、网页版本。

## 5. 反目标

- **不要"数值碾压制"**：如果最优解变成"无脑出攻击牌"或装备差距大到不用做选择，就算失败。火堆、精英路线、商店花钱都要存在真实的取舍。
- **不要把游戏写成小说**：事件文本一屏以内（约 15 行），战斗界面一屏放得下（状态+手牌+敌人）。文字量堆砌不算完成度。
- **不要退化成自动战斗**：每回合必须由玩家做决策；出现"跳过战斗直接结算"的设计就违背初衷。
- **不要等级系统以任何形式回归**：不出现 XP、"击杀 N 只怪物提升属性"这类隐性升级。成长只能来自装备/遗物/卡牌/火堆。

## 6. 术语与核心机制

### 6.1 一局流程与地图

- 勇士初始：HP 80/80、金币 0、初始卡组 10 张（6×打击、4×防御）、武器"锈剑"、无防具、无遗物。
- 地图为分层 DAG：纵向约 12~14 层，每层 1~4 个节点，节点间有连线通向下一层若干节点；玩家从入口层任一节点出发，每层沿连线前进一步。
- 顶层唯一节点是**魔王战**；魔王战前一层的节点都通向它。
- 节点类型：`战斗`（普通）、`精英`、`火堆`、`事件`、`商店`、`宝箱`。生成规则（建造者可微调，但须满足）：
  - 每局精英固定 2 个，分布在中后段（约 55% 与 85% 深度处），玩家沿路线是否踩到可选。
  - 火堆至少 3 处，其中第 4、8 层附近各保底一个（保证续航），魔王战前一个（最后准备）。
  - 商店至少 1 处。
  - 前两层不出现精英；入口层全部为普通战斗。
- 界面用 ASCII 画出整张地图，已过节点标记、可选下一步高亮，输入编号移动。
- 击杀、拾取即时结算，不可回头。

### 6.2 战斗流程

- 先攻判定：普通遭遇通常玩家先手；部分敌人词条要求先手（建造者决定意图可见下的公平性）。
- 玩家回合：抽 5 张牌，能量 3 点；出牌消耗能量，选择目标（若有多个敌人）；`结束回合` 后手牌全部进入弃牌堆。
- 牌堆：抽牌堆空时，把弃牌堆洗回。战斗内格挡（block）回合结束清零，不带到下个回合（除非遗物/防具另有说明）。
- 敌人回合：按已展示的**意图**执行（攻击 N×M、防御、强化、特殊）。意图在玩家行动前就显示，玩家据此决策。
- 敌人死亡立即移除；全部敌人死亡则战斗胜利，结算奖励（金币、卡牌三选一、可能掉遗物）。
- 战中 HP 归 0：本局结束，死亡结算屏，显示战绩统计。
- 状态词条只保留两种：**力量**（出牌攻击 +X，敌人也有）、**易伤**（受到的攻击伤害 ×1.5，每次触发 -1 层）。其余状态不做；仅**毒**（回合开始掉血、不衰减除非另有说明）允许作为药水与个别敌人/卡牌的专属效果存在。
- 卡牌奖励规则：战斗胜利后从卡池随机抽 3 张展示（可整组跳过），品质权重随深度提高。初始基础牌不入奖励池。

### 6.3 卡牌

- 基础牌：
  - 打击（1 费）：造成 6 点攻击伤害（受武器加成）。
  - 防御（1 费）：获得 5 点格挡。
- 卡牌池约 30 张，覆盖几类味道（具体列表与数值由建造者定，示例）：
  - 攻击变体：重击（2 费 12 伤）、连刺（1 费 3×2）、旋风斩（影响武器词条）、处决（对低血敌人增伤）等。
  - 技能：挑衅、战吼（抽牌）、格挡反击、蓄力等。
  - 能力牌（打出后持续生效、不占回合）：狂怒（每回合首次攻击 +3）等。
  - 少量带资源代价或 HP 代价的强力牌，制造取舍。
- **牌面伤害数值是基准值**；武器加成作用于所有带"攻击伤害"的牌（多段则每段加成）。

### 6.4 武器

- 同时只能装备 1 件。勇士的牌本身偏基础，武器是主要的攻击端成长。
- 武器 = 攻击伤害加成 + 一条特殊词条。示例（建造者定最终表）：
  - 锈剑（初始）：攻击 +0，无词条。
  - 旅行者长剑：攻击 +1。
  - 巨斩斧：攻击 +4，每回合第一次出牌额外消耗 1 能量。
  - 双刃：攻击 -1，每回合多抽 1 张。
  - 燃火之刃：攻击 +2，每回合开始时受到 2 点伤害。
- 获取：商店购买、宝箱、精英/事件奖励。换装即时生效，旧武器丢弃。

### 6.5 防具

- 同时只能装备 1 件。防具主要提供**战斗开始时**的格挡与生存词条。示例：
  - 布甲：战斗开始格挡 2。
  - 皮甲：战斗开始格挡 5。
  - 板甲：战斗开始格挡 9，每回合少 1 点能量。
  - 刺甲：战斗开始格挡 3，每回合对每个攻击你的敌人造成 3 点伤害。
- 获取途径与武器相同。

### 6.6 遗物

- 无数量上限，获得即永久生效（本局内）。覆盖三大时机：战斗开始、回合开始/结束、战斗结算/商店等全局效果。示例：
  - 炭炉石：每场战斗结束后回复 4 HP。
  - 战吼号角：每场战斗第一回合多抽 2 张。
  - 钱包：获得的金币 +25%。
  - 咖啡壶：每场战斗第一回合能量 +1。
  - 巨魔之牙：HP 低于 30% 时力量 +2。
- 获取：精英必掉（三选一）、boss 战前宝箱/魔王掉落、普通战斗约 15% 概率直接掉落、商店有售（贵）、特定事件。
- 稀有度分 普通/罕见/稀有/守卫（精英与 boss 专用），掉落权重随来源不同。

### 6.7 火堆

到达火堆节点，从以下选项中**选一个**：

- 睡觉：回复当前 HP 上限的 30%。
- 锻造：强化一张手牌（从可强化牌中选），强化永久作用于本局（改变数值或词条，如"打击→打击+：伤害 6→9"）。
- （建造者可加第三个选项，如"打磨武器：武器攻击加成永久 +1"，用于处理"买了武器没牌可强化"的死局。）

### 6.8 随机事件

- 8~10 个，每个 2~3 个选项，选项有明确或暗示的风险/收益（HP、金币、卡牌、装备、遗物之间交换）。示例方向：受伤的旅人（救/拿钱走）、赌博地精（押金币翻倍或对半）、神秘祭坛（献祭 HP 换遗物）、铁匠铺废墟（翻宝箱可能惊动怪）。
- 同一局内事件不重复。
- 文本一屏以内，选择用编号。

### 6.9 商店

- 每次到店货栏随机补：2 张牌、1 武器、1 防具、1 遗物、2 瓶药水（价格按稀有度浮动，建造者定表）。
- 商店可花金币移除一张牌（"删牌"服务常驻），这是卡组精简的主要手段，必须保留。
- 有金币打折类遗物时自动生效并显示原价/现价。

### 6.10 敌人、精英与魔王

- 敌人数量普通遭遇 1~3 只；同场怪物组合来自预定义遭遇表（建造者定，随深度换组合、加血量档）。
- 敌人行为全部走"意图"框架：每回合从固定招式循环/加权随机中挑选并公示意图。
- 精英：HP 与招式的量级明显高于普通遭遇，但有可学习的节奏（如蓄力→大打击循环），击败必掉遗物三选一 + 一笔金币。
- 魔王：单体，HP 约 140~180，两阶段：血量过半换招（进入带"力量成长"的狂暴循环），逼迫玩家在狂暴叠起来前结束战斗。击败即通关。

### 6.11 药水

- 携带上限 3 瓶，商店与事件、少量战利品获得；战斗内外均可用，用后消耗。
- 5~6 种：瞬间回血、临时能量、加攻击一回合、群体毒（毒=回合开始掉血，作为易伤/力量之外唯一例外——若建造者嫌多可并入"临时力量"）。

## 7. 界面（终端）

- 全程编号菜单 + 少量命令（战斗中：`1..n` 出牌、`d` 结束回合、`p` 用药水、`i` 查看遗物/牌堆详情）。
- 战斗画面固定结构（≤50 行、单屏内）：顶栏（HP/金币/能量/格挡）、敌人区（名称、HP、意图）、手牌区（编号、费用、效果一行一张）、日志尾 3~5 行。
- 地图画面：ASCII 分层图 + 当前状态栏。
- 非法输入不崩溃：重新打印菜单并提示。
- 屏幕刷新方式：`os.system('cls')` 清屏重绘（失败则直接追加输出，不影响功能）。
- 可选 ANSI 颜色（构建者决定，必须能在纯黑白终端下正常玩）。

## 8. 存档与记录

- **本局不落地**：战斗/地图状态只在内存；退出即放弃。
- 战绩文件 `records.json`（程序目录下）：累计局数、胜场、死亡最深节点、常用路线统计、总击杀。
  - 每局结束（死亡或通关）时写入一次。
  - 遵循仓库既有的存档安全纪律：临时文件 + `os.replace` 原子写；读档时"文件不存在 / JSON 损坏 / 暂时读不到（PermissionError 等 I/O 错误）"分开处理——损坏改名为 `records.corrupt-<时间戳>.json` 并从空记录继续，I/O 错误只提示、不覆盖。
- 种子可复现：开局可输入/指定随机种子（默认时间戳），同种子应生成同一张地图与同一掉落序列，便于测试与分享。

## 9. 结构与实现

标准库、Python 3.8+，无第三方依赖。文件划分（参考 milkCow/farmer 的 core/UI 分离惯例）：

```
warrior/
  main.py            # 入口：初始化 RNG、种子、records，进入终端主循环
  core.py            # 纯逻辑：战斗状态机、卡牌结算、地图生成、事件/商店、掉落
  content.py         # 数据表：卡池、武器、防具、遗物、药水、敌人、遭遇、事件文本
  ui.py              # 终端渲染与输入循环，只调 core 的公开接口
  records.py         # 战绩读写（原子写 + 损坏处理）
  test_core.py       # 单元测试：战斗结算、洗堆、意图、遗物触发、地图保证条件
  test_run.py        # 集成冒烟：注入种子 + 自动策略完整跑一局（含通关线），断言不崩、可胜
  test_records.py    # 存档安全：损坏/缺失/I/O 错误三路径
```

- core 不 print、不 input；所有随机走注入的 `random.Random(seed)`，逻辑不读系统时间（战绩时间戳除外）。
- 遗物/武器/防具/状态对战斗的介入统一走"钩子点"（战斗开始、回合开始、出牌结算、伤害结算、战斗结束、获得金币、商店定价），新增内容不改动流程代码。

## 10. 测试策略

1. **单元测试（test_core.py）**：出牌/格挡/死亡/洗堆/能量边界；力量、易伤结算顺序；每种遗物至少一条触发断言；武器加成对多段攻击的乘算；地图生成对第 6.1 节保证条件的断言（跑 1000 张随机地图）。
2. **整局模拟（test_run.py）**：简易自动玩家策略（优先攻击牌、血量低睡火堆）在多个种子下跑完整局，断言：不抛异常、能在魔王层抵达并胜利至少一种可胜路径、失败路径能正常走到死亡结算。
3. **存档安全（test_records.py）**：正常读写、损坏 JSON 改名重建、PermissionError 不覆盖原文件。
4. **终端人工验收清单**：`python main.py` 真机 cmd 与 Windows Terminal 各跑一局，检查一屏不溢出、非法输入提示、中文对齐不裁切（终端 CJK 宽度按 wcwidth 估算逻辑列宽即可，不追求像素级）。

## 11. 留给建造者的细节决定

以下不需要回头问用户，由建造者自行拍板（在计划/实现中说明为建造者决定）：

- 卡牌池、武器/防具/遗物/药水、敌人招式、事件文本的**最终列表与数值**（按第 6 节的框架与示例填充到要求的数量）。
- 金币产出与商店价格表、掉落权重曲线、每层节点数分布。
- 先攻规则、意图随机化方式（固定循环 vs 加权随机的比例）。
- 火堆第三选项（武器打磨）是否加入。
- 能力牌（持续型）的数量与形态。
- ANSI 颜色是否实装。
- 事件判定的随机性与显示透明度（明示概率或只标"危险"）。

## 12. 风险与取舍

- **数值平衡是最大的未知数**：十几分钟一局、无等级压制下，"够刺激但可通关"依赖掉落曲线调参。缓解：种子复现 + 自动整局模拟可以先用脚本扫一遍胜率，再人工微调；首版接受"偏难"，通关线明确可达即可。
- **纯文字的可读性风险**：战斗信息一屏装不下会让玩家盲打。缓解：第 7 节固定版面结构 + 人工验收列在测试策略里。
- **内容量与工期的矛盾**：30 张牌、20 个遗物是"手感"的底线，事件文本是"味道"的底线，两边都可以先粗后细——结构（钩子点、数据表）一次做对，内容后续可增补而不改代码。
- **roguelike 地图生成的隐藏死局**（比如路线无火堆导致必死）：靠 6.1 的保底规则 + 1000 图断言测试兜住，不靠运行时补救。
